一、统一公共模块，设备与任务独立扩展

围绕软件整体开展代码审查，清理重复保存的数据、多余接口和跨层依赖，梳理线程关闭与资源释放顺序。在此基础上，将软件拆分为独立仓库，形成设备和任务可以按需组合使用的公共模块。

HandleCore · 通信连接

统一串口、网络等收发机制，复用断线重连和关闭流程。

DeviceCore · 设备基础

提供设备运行、数据收集与访问管理的共同规则。

TaskCore · 任务基础

提供任务编排机制，统一不同类别设备的标准能力。

UICore · 公共界面

统一输入控件、收缩栏及设备和任务页面的布局。

ChartCore · 绘图显示

提供共享的二维图表和三维功率谱显示。

Algorithm · 算法计算

集中维护坐标换算、风场及功率谱等计算能力。

公共模块按需组合 → 具体设备与任务 → 主程序统一装配

每种设备和每类任务分别维护自身协议、业务及页面，主程序负责组合与展示。后续接入激光器、温控等设备，可以复用既有通信和界面能力，减少对已有采集功能的修改。

为 Windows 与 ARM Linux 共用代码建立基础

通信模块不再绑定某一端的界面。同一设备的协议实现可以供桌面程序和 Linux 端复用，避免两端分别维护相同的收发逻辑。

二、完成带界面的 Docker 仿真交付

完成仿真版本的 Linux 移植与运行验证，并打包为可在 Linux 桌面环境中运行的 Docker 镜像。通过命令行指定单轴、环形四轴或蛇形四轴任务，设备就绪后自动开始采集，同时显示界面、实时绘图并保存数据。

  • 设备参数通过 JSON 配置，任务参数通过命令行给出；默认风场采用线性剪切与随机起伏。
  • 验证三种任务的采样、落盘及停止退出，完成 Windows 回归和 Linux 桌面显示检查。
  • 已整理镜像、示例配置、启动脚本和部署说明，形成可直接转交测试的离线交付包。

交付范围

当前为仿真设备版本，面向 x86_64 Linux 桌面与 Docker 环境。界面显示及三种采集任务已验证；ARM 外围设备桥接属于后续工作。

三、完成激光器通信协议层

依据镭晟激光器协议，实现指令报文封装、CRC16 校验和不定长数据解帧。接收过程能够处理分段到达、连续多帧，以及错误报文后的重新识别，复用已有串口连接机制。

已通过 Windows、Linux 构建及 505 项测试断言，覆盖协议示例和主要异常报文场景。目前完成的是通信协议层；设备实机联调、控制页面和状态显示仍在推进。

本周阶段成果：公共模块与设备、任务分仓完成；带界面的 Linux/Docker 仿真版已交付；激光器协议层已具备后续业务接入基础。

下一步计划

  • 完善外围设备页面：完成激光器的界面控制、状态与报警显示，并开展温控设备接入。
  • 实现 ARM 端桥接器（Bridge）：基于 HandleCore 接入外围设备，建立各 Handle 设备之间的协议转发通道，使 Linux 端设备数据与 Windows 端界面连通。
